# 소닉 애니메이션 뷰어 PRD

## 1. 문서 기준과 목표

- 요구사항 원본: 같은 폴더의 `PRD-PRE.md`.
- 작업 브랜치: `feature/lec09-animation-viewer`.
- 목표: `sonic-sprite.png`에 담긴 모든 소닉 동작을 확대하여 순서대로 재생하는 Python 프로그램을 만든다.
- 개발 방식: 작은 기능 단위로 구현하고 확인한 뒤 커밋한다. 전체 작업은 약 20개의 의미 있는 커밋을 목표로 한다.
- 구현 계획과 요구사항을 먼저 작성하고 개발을 진행했다. 실제 구현 및 검증 결과는 9절과 10절에 기록한다.

## 2. 실행 환경과 산출물

| 항목 | 요구사항 |
| --- | --- |
| 언어 | Python |
| 그래픽 라이브러리 | pico2d |
| 구현 파일 | `Labs/LEC09/sprite.animation_viewer.py` |
| 이미지 파일 | `Labs/LEC09/sonic-sprite.png` |
| 프로그램 구조 | 프레임 데이터, 이벤트 처리, 재생 로직, 렌더링을 하나의 Python 파일에 작성 |

이미지는 실행 파일의 위치를 기준으로 읽는다. 실행한 터미널의 현재 폴더에 따라 이미지 로딩 성공 여부가 달라지지 않아야 한다. 실행에 사용하는 Python 환경에는 pico2d가 설치되어 있어야 한다.

## 4. 스프라이트 데이터 정의

### 4.1. 동작과 프레임의 범위

- 소닉 동작을 구성하는 프레임을 대상으로 한다. 제목, 설명 문구, 제작자 표기, 하단의 다른 캐릭터 그림은 재생 대상에서 제외한다.
- 원본 이미지를 위에서 아래로 분류한 그룹은 다음과 같다. 구현에서는 이 표와 동일한 `A01`~`A10` 식별자를 사용한다.
- 잘라낸 프레임과 원본 픽셀을 대조하여 10개 그룹, 총 76프레임을 확인했다. 대상 영역의 불투명 픽셀 45,746개가 누락이나 중복 없이 포함된다.

| 임시 그룹 ID | 원본 이미지의 위치 | 초기 프레임 수 |
| --- | --- | --- |
| A01 | 소닉 동작 1번째 줄 | 11 |
| A02 | 소닉 동작 2번째 줄 | 12 |
| A03 | 소닉 동작 3번째 줄 | 6 |
| A04 | 소닉 동작 4번째 줄 | 9 |
| A05 | 소닉 동작 5번째 줄 | 6 |
| A06 | 소닉 동작 6번째 줄 | 6 |

| A08 | 소닉 동작 8번째 줄 | 8 |

| 합계 | 10개 초기 그룹 | 76 |

### 4.2. 프레임 좌표와 출력 규칙

- 프레임마다 원본 이미지에서의 `left`, `bottom`, `width`, `height`를 명시적으로 등록한다. 균일한 격자라고 가정해 좌표를 일괄 계산하지 않는다.
- 좌표는 pico2d의 왼쪽 아래 원점을 따른다. 이미지 위쪽 기준 `top` 좌표를 측정했다면 `bottom = 이미지 높이 - top - height`로 변환한다.
- 모든 프레임의 폭과 높이는 양수이며, 잘라낼 영역이 원본 이미지 경계를 벗어나지 않아야 한다.
- 프레임에 캐릭터 전체가 포함되고, 이웃 프레임이나 제목 및 제작자 문구가 섞이지 않아야 한다.
- 출력 크기는 `width × 확대 배율`, `height × 확대 배율`로 계산한다. 가로세로 비율을 유지한다.
- 프레임별 여백이나 크기 차이로 캐릭터가 불필요하게 흔들리지 않도록 출력 기준점과 오프셋을 정한다. 동작 자체의 자세 변화는 유지한다.
- 최대 출력 크기와 오프셋을 고려해 모든 프레임이 캔버스 안에 표시되도록 한다.

## 5. 재생 동작

### 5.1. 사용자 시나리오

1. 사용자가 프로그램을 실행한다.
2. 800 × 600 캔버스가 열리고 첫 동작의 첫 프레임이 확대되어 표시된다.
3. 첫 동작을 5회 재생한 후 마지막 프레임을 1초 유지한다.
4. 다음 동작의 첫 프레임부터 같은 규칙으로 재생한다.
5. 마지막 동작의 정지가 끝나면 첫 동작부터 다시 시작한다.
6. 사용자가 Escape 키를 누르거나 창을 닫으면 프로그램이 종료된다.

### 5.2. 반복 횟수와 전환 규칙

- 한 번의 반복은 해당 동작의 첫 프레임부터 마지막 프레임까지 모두 표시한 경우다.
- 첫 프레임과 마지막 프레임을 포함한 모든 프레임을 설정된 시간 동안 표시한다.
- 1~4회 재생이 끝나면 같은 동작의 첫 프레임으로 돌아간다.
- 5회 재생의 마지막 프레임 표시 시간이 끝나면 정지 상태로 들어간다.
- 정지 상태에서는 프레임과 출력 위치를 바꾸지 않고 1초를 기다린다.
- 정지가 끝나면 다음 동작으로 넘어가며 프레임 번호, 반복 횟수, 경과 시간을 초기화한다.
- 다음 동작 인덱스는 전체 동작 수를 기준으로 순환한다.
- 프레임이 하나뿐인 동작이 있다면 해당 프레임을 5개의 프레임 표시 시간 동안 유지한 뒤 1초 정지한다.

### 5.3. 시간과 이벤트 처리

- 재생과 정지는 실제 경과 시간을 누적하여 처리한다. 렌더링 루프 실행 횟수를 시간으로 간주하지 않는다.
- 초기 재생 속도에서 N개 프레임으로 구성된 동작의 재생 시간은 `N × 0.1초 × 5회`이며, 이후 1초 정지가 별도로 붙는다.
- 동작 전환 중 프레임 건너뛰기, 반복 횟수 중복 증가, 정지 시간 누락이 발생하지 않도록 한다.
- 재생 상태와 정지 상태 모두에서 매 루프 이벤트를 처리한다. 1초 정지를 긴 블로킹 대기로 구현하지 않는다.
- 불필요한 CPU 사용을 줄이기 위해 루프에 짧은 대기를 둘 수 있지만, 재생 시간 계산은 실제 경과 시간을 기준으로 유지한다.

## 6. 오류 처리

- 이미지가 없거나 읽을 수 없으면 파일 경로와 실패 이유를 알 수 있는 메시지를 출력하고 종료한다.
- 프레임 목록이 비어 있거나 좌표가 이미지 범위를 벗어나면 해당 동작과 프레임을 식별할 수 있는 오류를 알린다.
- 정상 종료와 실행 중 오류 발생 시 모두 열린 캔버스를 정리한다.
- 상태와 설정은 이름이 명확한 상수, 함수, 프레임 데이터로 구분하되 단일 파일 구조를 유지한다.
